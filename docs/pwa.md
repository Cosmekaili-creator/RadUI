# Installable app and service worker

RadUI installs as a Progressive Web App (Android and desktop Chrome/Edge, iOS "Add to Home Screen") and
opens without a network connection, read-only. Nothing about calendars or contacts is stored on the
device: the worker caches the application files only.

| File | Role |
|---|---|
| `src/manifest.webmanifest` | Name, `start_url` and `scope` `"./"` (relative: correct under any base path), `display: standalone`, icons (any + maskable), one shortcut "New contact" (`./#/contacts/new`). |
| `src/sw.js` | The worker (classic script). |
| `src/sw-manifest.js` | Generated by `tools/build-sw-manifest.py`; not in git. The list of files to precache with one SHA-256 each, and the version. |
| `src/js/pwa.js` | Registration and the update banner. |
| `src/i18n/{en,fr}.pwa.js` | Messages only the PWA module shows (the banner text and button are `shell.update.*`). |

## Build

`make build` writes `src/sw-manifest.js` (`make clean` removes it). The generator lists every file under `src/`
except `sw.js`, `sw-manifest.js`, `package.json` (top level), `.gitkeep`, `README.md` and `vendor/**/SHA256SUMS`.
Version = first 16 hex digits of the SHA-256 over the sorted entries, each `<path> NUL <sha256> LF`. The output is
deterministic. `--src DIR --out FILE` builds another tree into another file (tests and E2E runs build into their
run directory, never into `src/`).

`config.json` is deployment-specific (the live copy differs from the source copy), so it is listed with
`"sha256": null`: not verified, not part of the version, served network-first.

## Distribution build (`make dist`)

`src/` stays the readable source (AGPL-3.0-or-later). `make dist` runs `tools/build-dist.py` and writes the
git-ignored `dist/`: every `js/**/*.js` and `sw.js` minified one file at a time with the system `terser`
(compress + mangle, class names and the SPDX comment kept, no `unsafe*` options; `vendor/` byte for byte), each
language's dictionary flattened into one file `i18n/<lang>.js` (the part files are not in `dist/`; node proves the
flattened dictionary equals the one the source aggregator builds, otherwise the build fails), and
`build-info.json` (`source` = `git describe --always --dirty`, `minified`, `terser`; no path, host or user).
`sw-manifest.js` is not in `dist/`: `tools/deploy-static.sh --src dist` builds it from the tree it is given, so the
precache list and its hashes describe exactly what is served. The build is deterministic. It refuses an `--out`
inside or equal to `--src`, one that contains it, `/`, the home directory, a symlink and a non-empty directory
that is not a previous build. `make dist DIST_FLAGS=--no-minify` builds without terser.

`make size` (or `tools/size-report.py --www dist`) prints raw/gzip sizes and checks the budget: the gzip-6 size
of the **first calendar screen** (static-import closure of `js/app.js`, `model/item.js`, `store/index.js` and the
screen module, plus one dictionary) must stay at or below 250 KB (`--budget-kb`). The whole precached app is
bigger; it is fetched after the first paint. Browser suites can serve the built tree:
`make test-e2e E2E_SUITE=<name> E2E_WWW_FROM=dist` (or `RADUI_E2E_WWW=dist`).

## Worker rules

- **Install.** Every listed file is fetched with `cache: 'reload'` (bypasses the web server's `max-age`), its
  SHA-256 is compared with the list, and it is stored in `radui-shell-<version>`. Any HTTP error, redirect, network
  failure or hash mismatch FAILS the install and the half-filled cache is deleted: a version is cached completely
  and verified, or not at all (no mixed trees, even if the deploy copy is still running).
- **Activate.** Older `radui-shell-*` caches are deleted, then `clients.claim()`.
- **No runtime caching.** The worker never writes to a cache outside the install step.
- **Fetch is an allowlist** (GET, same origin, inside the scope):
  - listed files: cache-first (a miss goes to the network and is not stored);
  - `config.json`: network-first; the precached copy answers when the network fails or the server answers 5xx;
  - navigations to `./` or `index.html`: cache-first from the precached `index.html` (network only on a miss), so a
    new `index.html` never runs against old modules; the update banner performs the reload;
  - everything else is left alone (the worker does not call `respondWith`): CalDAV/CardDAV paths, `api/`, unknown
    paths, other methods, other origins, requests with a query string or a `Range` header.
- **Updates wait.** No `skipWaiting` until the page posts `{type: 'SKIP_WAITING'}`. `{type: 'GET_VERSION'}` is
  answered with `{type: 'VERSION', version, cache}` on the message port.

## Update flow (`js/pwa.js`)

1. The page registers `sw.js` (relative) with `{scope: './', updateViaCache: 'none'}`, after `load`, on a secure
   context or localhost only. Without service worker support nothing happens; no failure reaches the app.
2. When the page becomes visible, `reg.update()` runs, at most once an hour.
3. A waiting worker (with an older one in control) shows `banner-update` (`role="status"`) and `btn-reload-update`.
4. The button first asks the shell's "Discard unsaved changes?" question when a form is dirty, then posts
   `SKIP_WAITING`; the page reloads when `controllerchange` arrives (once). If it does not arrive within 10 s the
   banner says so (`pwa.update.stuck`).
5. A tab that did not press the button never reloads by itself. If another tab applied the update (an unrequested
   `controllerchange`), this page still runs the old modules while its lazy imports would be served from the new
   cache, so it marks itself stale: the write gate gets the reason `update` ("Reload to continue"), and the banner
   stays with a reload button until the page reloads (the discard question comes first if a form is dirty).

Hook in `js/app.js`, after `translateStatic(); updateChrome(null);` and before `await router.start();`:

```js
import { initPwa } from './pwa.js';
// ...
initPwa({ win, doc, t, guarded: (fn) => leave.guarded(fn) });
```

## Recovery: removing a bad worker

A worker that pins a broken app is replaced by deploying `deploy/sw-selfdestruct.js` as `sw.js` (it is NOT part of
the shipped tree and is not listed in `sw-manifest.js`; unit test: `tests/unit-js/pwa/selfdestruct.test.mjs`).
Serve it with `Cache-Control: no-cache` and keep it for at least the update interval (a day or more), then deploy
the real `sw.js` again. Browsers re-check `sw.js` on navigation (at most daily) and when the page becomes visible
after an hour; the new worker deletes the `radui-shell-*` caches, unregisters itself and reloads the open pages from
the network. `tools/deploy-static.sh` prints this as part of the rollback when the previous deployment had no
`sw.js` (see [UPGRADE-UI.md](UPGRADE-UI.md)). The worker is:

```js
self.addEventListener('install', () => {
  self.skipWaiting();
});

self.addEventListener('activate', (event) => {
  event.waitUntil(
    (async () => {
      for (const name of await caches.keys()) {
        if (name.startsWith('radui-shell-')) await caches.delete(name);
      }
      await self.registration.unregister();
      for (const client of await self.clients.matchAll({ type: 'window' })) {
        try { client.navigate(client.url); } catch (_err) { /* the user reloads */ }
      }
    })(),
  );
});
```

Users can also clear the site data in the browser settings.

## Web server

`sw.js`, `sw-manifest.js`, `manifest.webmanifest`, `index.html` and `config.json` need `Cache-Control: no-cache`
(`deploy/nginx/radui-locations.conf.tpl`, checked by `make test-deploy`). The `sw-manifest.js` location was added
with the cache-first navigation design: a stale list would let a new worker precache a mixed tree.
**Applying the new location to a live nginx is a gated deployment step (the operator's explicit go): diff the
live snippet against the rendered template, back it up, apply, `nginx -t`, reload.** Deploy order: all files, then
`sw-manifest.js`, `sw.js` and `index.html` last.

## Deploying

`tools/deploy-static.sh` builds `sw-manifest.js` into a temporary copy of `src/`, refuses to run if its own file
list differs from the generator's, backs up the served directory, copies assets, then `js/`, then `sw-manifest.js`,
`sw.js` and `index.html` last, and checks every manifest hash in place. Procedure, nginx check with `curl`, what
open tabs show and rollback: [UPGRADE-UI.md](UPGRADE-UI.md). The recovery worker above is installed by hand, not
with the tool.

## Tests

`node --test tests/unit-js/pwa` (the worker runs in a `node:vm` sandbox with fake `self`, `caches` and `fetch`;
`pwa.js` runs against fake `navigator.serviceWorker`), `python3 -m unittest discover -s tools -p 'test_*.py'`
(generator), `make test-deploy` (headers). The browser suite `pwa` covers installability, the offline banner, the
update flow and the real worker behaviour (see `docs/testing.md`).
